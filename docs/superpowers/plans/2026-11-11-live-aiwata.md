# 接入真实 AIWATA 网关

目标是保留用户选择页，在本机工作台调用真实 AIWATA。林晓与乔安使用不同的 AIWATA 数据根和项目目录。联调改动留待验收。

- [x] 在单独的回环预览入口接入 AIWATA 原生取票。复用已安装的依赖。验证两个用户分别访问自己的网关项目，且切换用户后旧连接失效。
- [x] 将真实项目、会话和 Agent 接入现有工作台。验证首次发送的接纳、流式回复、审批和停止，以及重连时的状态恢复。
  已在浏览器验证项目创建和重命名、真实工具读项目文件及刷新恢复。网关实测了追问重连后作答和停止结算。浏览器在真实终端工具运行时刷新，恢复了运行状态并收到一次最终回复。手动审批模式下，刷新后仍可拒绝原审批，真实执行随后结算。验收后恢复了演示账号的审批配置。
  会话管理复用现有菜单和回收站。通过 `session.resume` 取得修改版本，走 `session.mutate` 写入。原生列表省略目录和归档状态，本机桥接从独立账号的状态库读取目录和归档状态。已在浏览器验证重命名、归档刷新后显示、恢复、移动后重新加载和删除确认。网关拒绝删除执行中的会话，拒绝跨账号恢复和移动到其他账号目录。模型状态来自 `setup.runtime_check`。
  丢弃真实发送的 HTTP 响应后，按原提交 ID 找回回执，重连后只恢复一条用户消息和一条回复，另一账号无法查询。在独立验收环境终止等待追问的网关进程，浏览器显示中断处理入口。结束原请求后，同一会话再次得到真实模型回复。
