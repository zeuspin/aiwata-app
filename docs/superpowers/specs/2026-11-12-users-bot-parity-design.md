# 虚拟用户与 Bot 原生能力完整保留

状态：用户已批准执行（2026-11-12）；归档入口与清理说明另行先完成源码修改。没有发布、覆盖安装或迁移真实数据。

## 已确认需求

登录页默认提供两个可选择的虚拟用户；无需注册、密码或商业账号服务。输入用户名即可创建用户，并支持删除。用户需要用此入口验证不同用户的数据与运行作用域分离。Bot 的操作在 App 内保持原生完整性。主导航栏底部回收站移入头像卡片，名为归档记录；展示真实自动清理时间规则。

## 方式与约束

采用“本机用户登记 + 独立原生数据根 + 用户下面的 Bot Profile”。原生 Electron、原 Agent、原 gateway ensure、凭据、审批继续负责现有职责。仅增加本机身份登记与所属路由，不增加账号服务器、Agent执行体系或容器。

只增加两个前端账号对象会共用当前后端数据，无法验收隔离；直接把 Bot Profile 变成用户也会混淆已确认的两层身份，因此这两种方式不满足需求。

## 用户操作

- 登录页展示“用户一”“用户二”，标注本机虚拟用户；默认不自动登录。输入用户名创建后立即出现新用户卡片，随后由用户点击进入。
- 用户ID为宿主生成的稳定随机ID；显示名不用于目录拼接。限制空白、过长及重复名称，重名不覆盖已有用户。
- 每张卡片提供删除入口，确认框明确用户名与数据处理规则。用户明确确认这些均为测试数据：删除用户时确认后删除该用户登记及所属测试数据，不保留。必须限定到宿主登记的用户目录，停止该用户所属运行后清理，不删除安装、共享工具或其他用户数据。删除最后一个后展示空态与创建入口，不自动补回已删除用户。默认两用户只在登记首次初始化时创建。
- 删除登记前确认；删除后关闭该用户的客户端连接、禁止从旧登记建立新请求，删除时通过原网关生命周期停止该用户的所属任务，确认无所属活跃窗口/写入后清理；普通退出/切换仍保留后台任务。退出登录回到选择页；重开仍显示选择页。辅助原生窗口继续沿用创建时的用户所属，不被另一个窗口的登录改变。

## 所属与兼容

所有测试用户采用宿主控制的独立用户目录，不把安装/共享工具所在的旧默认根作为可递归删除的用户目录。无需迁移或保留旧测试内容，亦不因此自动删除未绑定旧根。用户一、用户二及新增用户使用宿主控制的独立用户数据根，各有 config、认证存储、会话、记忆、默认文件目录、连接登记与其 Bot profiles。根目录由宿主现有路径解析器推导，不硬编码全局目录。

宿主维护无凭据的原子登记文件；读取损坏或失败必须报告错误，不能当成首次启动并重新创建两用户。创建或切换失败停留在原用户/选择页，不能回退进入其他用户工作区。renderer只能调用有类型的 list/create/remove/activate，不能传入任意本地数据根路径。所有窗口的route、API、WebSocket ticket、PTY、文件/浏览器分区、授权弹窗和后台回调带稳定userId与generation；迟到结果不能进入新用户。现有main的HERMES_HOME是进程常量，profile:set仅重置主连接和重载，并不已支持任意用户根。必须先建立按窗口固定的userId→home路由及原生桥接解析，再重载renderer；不能全局改home或全进程relaunch后声称辅助窗口仍保留旧所属。实际实现按用户启动原Electron宿主的独立进程，以不可变home固定所有原生桥接的所属；辅助窗口继续属于创建它的实例。原安装的已提交PM依赖状态通过宿主验证后借用，不复制用户凭据、不创建新的依赖环境。更换数据根在完成上述路由后按hard re-home规则重载；后端任务继续由原网关管理，不为切换强停后台任务。

原宿主目前启动根固定、多个桥接只接受connection/profile；实现必须逐一打通该边界，不能只改localStorage命名。共享发行基础模型的既有加载规则保留，用户自填凭据不从其他用户复制。已有远端/SSH连接先保持所属登记，不能默默对所有用户公开。

## Bot 功能验收

当前实际差距：原生的模型选择目录、技能安装/详情、工具集参数、完整MCP管理，在新Bot编辑器主要缩减成勾选及手填。native bot roster也未提供旧联调identity，而删除按钮仍依赖该字段，须按原生路由/版本验证机制接通删除，不能只解除disabled。

按相同后端版本/连接/Profile/配置逐项对照：

1. 创建、克隆、显示名称、简介、头像、SOUL与持久化重开。
2. 原模型目录选择、自定义供应商、原模型确认/授权及取消。
3. 原技能目录安装、启停/锁定、详情/编辑/卸载；工具集启停及参数；MCP配置/授权/取消；消息连接器与记忆、任务所属。
4. Bot canonical永续会话的首次创建、并发采用、压缩续接、附件、历史工具详情、桌面请求、审批、停止、断线恢复。
5. 原生群聊的成员/路由/远端加入、审批/停止/重试、后台完成与冷恢复；所有用户只见其所属Bot与群。
6. 原生删除/隐藏等菜单操作逐项核对。可复用原完整能力页面，但必须固定到目标Bot的connection/Profile；不能误开用户默认Profile页面，也不能只用“高级设置”链接声称整体齐平。

优先复用现有完整原生页面与typed nativeSurface；新界面继续承担已约定的交互职责。查到需要改Agent行为或新增权限的冲突时单独记录并按工程规则确认。

## 归档说明

入口位于头像卡片，名称统一为归档记录。保留现有归档、恢复和会话菜单，键盘关闭后回焦头像。

打开时读取当前工作区的/api/config sessions配置。未启用auto_prune明确写未启用；启用则展示retention_days与min_interval_hours，说明已结束、未置顶且满足闲置条件才可能被维护清理。自动归档不是删除，不从归档时间起倒计时。未提供last-run/next-run契约时不伪造精确删除日历时间；读取失败不伪装成已关闭。

## 验证和交付

先验证登记损坏不会重建默认用户、创建/切换失败不会误入其他工作区，再在隔离临时目录验证两个用户交替登录、同名Bot、不同模型配置/凭据、会话/记忆/文件/连接、草稿/附件/UI偏好，以及A用户迟到回调不能污染B用户。实际原生宿主做相同用户切换和冷重开，不使用真实用户会话发测试消息。用户删除须确认并验证重开不复活、所属测试数据已清理且其他用户数据不受影响。

Bot按上述矩阵给出通过/失败/未验证，fixture不能冒充真实供应商/系统权限通过。归档验证入口位置、真实配置、错误状态与迟到响应保护。前端完整测试、native构建、核心相关合同测试与scripts/check按改动范围执行；确认不会间接创建容器后运行。最后同步两工程约定、维护批次与源码指纹。

源码实现、隔离验收与覆盖已安装App是独立阶段。本请求不解释为授权覆盖/重启日常App；不新建分支，不提交或推送，不创建容器，仅清理经本机用户登记确认的测试用户数据。

只读builder check已完成：已纳入宿主常量与按窗口路由的区别、删除时的运行状态、登记损坏与切换失败恢复。复核未执行产品实现或修改真实用户数据。

实现补充：全局Quick Entry由最后聚焦用户持有，父登录窗口不注册；截图/HUD手势也在触发时复核所属。退出工作区后当前用户可通过原生父子IPC请求父窗口完成自身停机和删除；父连接缺失时提示从父登录窗口恢复处理，未知占用不强杀。
