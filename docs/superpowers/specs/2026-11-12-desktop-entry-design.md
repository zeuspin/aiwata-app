# Unified AIWATA desktop entry

User approved the offered public desktop entry strategy on 2026-11-12. `/Applications/AIWATA.app` becomes the real original Electron desktop after successful native installation; the installer is only for install/upgrade/repair. No Agent, Profile, credentials, native provider, data-root or backend changes. No branch/commit/push. Current installed app is not replaced until the new candidate and controlled tests are reviewable.

Alternatives considered: retaining the launcher only shortens the two-process handoff and leaves a second application identity; hiding the actual desktop or changing bundle IDs would mask it. User selected real desktop publication. Use the existing signed app and embedded install stamp; avoid symlink launchers or another runtime.

Native installer publishes a validated desktop bundle via same-volume staging and rename, retaining the old target until publication and its ownership receipt succeed. Only an AIWATA installer or a desktop belonging to this source home can be replaced; reject unknown apps, links, or running desktops. Preserve a complete installer bundle under the same data home's hidden installer cache for explicit repair. Normal launches use the public desktop; legacy internal build locations remain a compatibility fallback until successfully promoted. Remove only the newly promoted, verified, rebuildable internal app to avoid duplicate indexed app copies.

New Mac DMG contains a distinctly named AIWATA Installer app, launched directly, rather than asking users to drag an installer over their real desktop. The public desktop remains AIWATA/com.aiwata.aiwata; installer stays com.aiwata.setup. Native repair opens the cached complete installer with --repair, following existing quit/approval behavior; never delete runtime markers or user data to trigger repair. Source download/build/activation failures preserve the current public desktop. Post-publication runtime failure keeps a retryable installer and valid desktop bundle, rather than declaring chat readiness.

Verify transaction rollback and wrong-home rejection with temporary filesystem apps; verify signed native copying and stamp-preserved launch in an isolated home/target before any real installed-app replacement. Existing snapshot activation and update fences remain in force. Windows/Linux package behavior remains unchanged; previous cross-platform window chrome fixes remain.
